# Матрица контроля

Официальное Приложение 1 к ТЗ в переданном PDF отсутствует (вопрос 1
организатору). До его получения реестр ведётся как черновик:
`matrix_version: draft-0`, у каждого правила `"source": "draft"`.

## Структура

```text
sections.json        соответствие разделов матрицы и документов ПД/РД/ИД (ТЗ п. 6)
params.template.csv  колонки таблицы Params из ТЗ п. 8.1 — формат импорта Приложения 1
rules/<CODE>.json    скомпилированное исполняемое правило (rule.schema.json)
```

## Процедура добавления параметра

1. Строка Приложения 1 импортируется в `params.template.csv` без изменений.
2. Текстовый `trigger_logic` компилируется в `rules/<CODE>.json` вручную или
   черновиком модели; черновик обязателен к юридической проверке (ADR-0004).
3. Правило получает минимум четыре фикстуры: положительную, отрицательную,
   граничную и legal. Правило без фикстур не попадает в релиз.
4. Проставляется честный `coverage`. Только `executable` участвует в
   автоматической проверке; `advisory` показывается инспектору без вердикта.

## Отчёт покрытия

`coverage_report` обязан публиковаться в разбивке
`executable / extractor_missing / source_missing / advisory / not_applicable`.
Формулировка «реализовано 132 параметра» без этой разбивки запрещена.
