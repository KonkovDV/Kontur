# Контур — правила работы в репозитории

Сервис сверки ПД/РД/ИД по 132 параметрам (задача №10, Мосгосстройнадзор).
Не BIM-платформа, не CDE, не замена инспектора. Отдельный приватный
репозиторий; `C:\AeroBIM` — донор архитектурных решений, но не зависимость
и не submodule.

## Инварианты, которые нельзя нарушить

1. `CONFIRMED_VIOLATION` создаёт только инспектор. Автомат выдаёт `CANDIDATE`.
2. LLM/VLM не пишут `finding_status` и не меняют результат компаратора.
   Разрешённая роль модели: извлечение кандидатов и черновик объяснения.
3. Предметная находка без `evidence_group_id`, `file_id`, SHA-256 источника,
   страницы и нормализованного bbox/polygon не сохраняется.
   `MISSING_EVIDENCE` / `NOT_APPLICABLE` могут быть без фрагментов.
4. Комплектность (`PD_/RD_/ID_UPLOADED/PARTIAL/MISSING`) и статус находки —
   разные домены. Процесс (`COMPLETED`/`FINALIZED`) и протокол
   (`VERIFICATION_COMPLETED`/`PROTOCOL_FINALIZED`) — проекции, не смесь.
   Отсутствие стадии никогда не становится нарушением. Пустой пакет — ошибка
   входа, не сценарий. Три загруженные стадии без заданного ожидаемого
   состава — `PARTIALLY_LOADED`, не `FULL`.
5. Эталон ПД — последняя применимая утверждённая редакция в цепочке
   predecessor/successor. Нет сведений об утверждении или цепочка
   противоречит — `CLARIFICATION_REQUIRED`, пока инспектор не выберет файл.
   Явный «не утв.» не перекрывается. РД и ИД не требуют утверждения:
   берётся последняя редакция шифра; `NOT_APPROVED` блокирует сравнение.
   `TITLE_BLOCK` и `INSPECTOR_SELECT` сохраняются. Конфликт не становится
   выводом о нарушении.
6. Нормативная ссылка хранится с `effective_from`/`effective_to`. Матрица
   организатора (`matrix_version`) — контракт соревнования; действующая норма —
   отдельный overlay-слой. Молча «исправлять» матрицу нельзя.
7. Координаты хранятся в исходной системе страницы и нормализованно [0;1]
   после CropBox/MediaBox/Rotate. Хранится polygon, bbox — производное.
8. `test_213` и любые `annotated_documents` скрытого теста — карантин.
   Запрещено использовать для выбора модели, порогов, prompt и regex.
9. Разбиение train/validation — строго по `object_id`.
10. Каждый результат несёт `matrix_version`, `dataset_version`, `model_version`,
    `input_manifest_hash` и git SHA.
11. `AUTO_NO_DIFFERENCE` не сериализуется в протокол ТЗ и в РиН до ответа
    на вопрос 8. `coverage: executable` ставится только при рабочем экстракторе.
12. Не утверждать, что вопросы организатору отправлены, пока в репозитории нет
    артефакта отправки. Не публиковать точность > порога ТЗ как достигнутую.
13. Сверка — ПД↔РД↔ИД, не проект против СНиП/СанПиН. Overlay нормы не меняет
    вердикт матрицы (ADR-0006).
14. Параметр не найден в **загруженном** документе — `LOW_QUALITY` / `ABSTAIN`,
    не `CONFIRMED_VIOLATION` и не `NEGATIVE_VERIFIED`. Нет документа стадии —
    `MISSING_EVIDENCE` / `NOT_APPLICABLE`.

## Порядок работы

- Контракт первичен: правка `contracts/` → схемы → код → тесты.
- Каждое правило матрицы — данные в `data/matrix/`, не код.
- Любая задача имеет `requirement`, `artifact`, `test`, `metric`, `stop_condition`.
- Порог считается достигнутым только по нижней границе 95% CI на validation.
- Новый статус находки добавляется только вместе с переходами в state machine
  и тестом запрещённых переходов.
