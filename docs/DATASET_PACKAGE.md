## Карантин: имя файла оказалось не тем, что ожидал код

Скрытый тест приехал как `РАЗМЕЧЕННЫЙ_TEST__213.zip` — с **двумя**
подчёркиваниями, а внутри лежит каталог
`РАЗМЕЧЕННЫЙ_TEST_HIDDEN_ОРГАНИЗАТОР_213`. Прежний детектор искал подстроку
`TEST_213` и на реальном имени **не срабатывал**: защита от утечки молча
пропускала карантинный архив. Теперь сравнение идёт по нормализованному имени
(`evaluation/inventory.normalize`: повторяющиеся `_` схлопываются, регистр
снимается, включая кириллицу), а расхождение детектора и манифеста ловит
`backend/tests/test_dataset_package.py`.

Каталог `annotated_documents/` есть и в открытом train, и в скрытом тесте.
Детектор **не** считает это имя карантином само по себе: иначе распакованный
train стал бы неотличим от запрещённой разметки. Карантин — маркеры скрытого
теста и дерево `data/quarantine/`.

Правило не изменилось: карантин не распаковывается, не просматривается и не
используется для выбора модели, prompt, regex, порогов и препроцессинга
(см. [`DATA_QUARANTINE.md`](DATA_QUARANTINE.md)).

## Открытая разметка

`РАЗМЕЧЕННЫЙ_TRAIN_PUBLIC_203.zip` — единственный источник разметки, с которым
разрешено работать. Структура пакета разметки:

```text
annotated_documents/     размеченные документы
data/                    исходные материалы
QA_SUMMARY.json          сводка контроля качества разметки
SHA256SUMS.jsonl         контрольные суммы
VALIDATION.json          результат валидации
ПАСПОРТ_РАЗМЕТКИ.pdf     состав полей и правила разметки
```

Порядок работы: сверить `SHA256SUMS.jsonl` → прочитать паспорт разметки →
вытащить перечень классов и `reason_code` → сопоставить с
`contracts/schemas/*.json` и `data/matrix/`. Расхождение схем фиксируется как
вопрос организатору, а не правится «по месту».

## Открытая разметка: корпуса и сплиты

`split_policy.json` (в обоих открытых пакетах) фиксирует официальное разбиение:

- **TRAIN_PUBLIC**: `OBJ-TYUMENSKAYA-5-GOLD-SEED` (58 файлов, GOLD_SEED),
  `OBJ-NOVOSLOBODSKAYA` (145 файлов, UNLABELED_POOL);
- **TEST_HIDDEN**: `OBJ-RECHNIKOV-7-7` (213 файлов, `ORGANIZER_ONLY`);
- исключены из корпуса: `F0149` (дубль по SHA-256), `F0418` (повреждённый PDF).

При этом сами **документы** Речникова лежат в открытом пакете
`01_ДОКУМЕНТАЦИЯ\Речников ул. 7-7` — без разметки (UNLABELED). Это утечка
корпуса, но не ответов: использовать его для обучения, подбора порогов, prompt
и препроцессинга запрещено теми же правилами, что и карантин; обработка —
только конкурсным прогоном pipeline. Барьер `require_open` это не ловит
(документы без маркеров) — изоляция держится на списке `object_id`, поэтому
любой dataset builder обязан фильтровать по allowlist TRAIN_PUBLIC, а не по
blocklist карантина.

Паспорт разметки v0.1: 3 подтверждённых нарушения, **0 подтверждённых
отрицательных**; UNLABELED ≠ NO_VIOLATION. `public_gold_checks.jsonl` —
15 проверок (10 VIOLATION_PRESENT / 5 NO_VIOLATION, последние помечены
`score_eligible: false`). Из десяти позитивов четыре — `FREE-HEATING-001`
(вне матрицы). В матрице для скоринга остаются **6** позитивов
(`IOS4-079` ×1, `IOS4-078` ×5). Это gold-seed TRAIN_PUBLIC, не frozen
validation: сплита `validation` у организатора нет, 106 критических не
размечены, Wilson на 6/6 не берёт порог recall ТЗ. Подробности и запрет
закрывать гейт J — [`ORGANIZER_GOLD.md`](ORGANIZER_GOLD.md).

13 119 `MATRIX_FIELD` в `annotations.jsonl` имеют статус
`AUTO_FIELD_CANDIDATE` и **не** являются экспертным gold сверки.

## Объекты и разбиение

Девять объектных архивов (10–18) плюс сводный `01_ПАКЕТ_УЧАСТНИКАМ_3_ОБЪЕКТА.tar`
с тремя объектами, идентификаторы которых из имени не видны. Адреса в
`objects.json` выведены из имён архивов и организатором не подтверждены:
источник истины — титул и штамп документа.

Разбиение train/validation проставляется только после инвентаризации и только
по `object_id`; пересечение должно быть нулевым. Перед разбиением — проверка
дубликатов по content hash между сводным пакетом и объектами 10–18: один и тот
же объект под двумя именами сломает изоляцию.
