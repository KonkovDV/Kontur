# Триаж числового семейства: какие `number`-правила стали исполняемыми

Документ фиксирует разбор 57 правил матрицы с `extractor.type = "number"`, которые оставались
`extractor_missing` после триажа семейств `exact_field`/`presence` и триажа лестниц классов.

Машиночитаемая версия: `data/matrix/number_family_triage.json`.

## Выборка

В выборку попадает правило, у которого одновременно:

- `coverage == "extractor_missing"`;
- `extractor.type == "number"`;
- код ещё не разобран в `family_triage.json` и `class_ladder_triage.json`.

Таких правил 57. Выборка пересчитывается из `data/matrix/rules/*.json` и проверяется тестом,
поэтому «забыть» правило нельзя.

## Правило перевода в `executable`

Числовое правило становится исполняемым только когда выполняются все три условия:

1. **Параметр объявляется одним числом.** По нормативу или сложившейся практике он стоит
   отдельной строкой с устойчивой подписью в текстовом документе (теплотехнический расчёт,
   энергетический паспорт, сводный сметный расчёт, лист общих данных).
2. **Не нужен обмер, подсчёт или разбор таблицы по строкам.** Ширину коридора измеряют
   по чертежу, извещатели считают на плане, диаметры стояков перечисляют по участкам —
   всё это другой вид доказательства.
3. **Единица измерения одна.** Пункты вида «шт. / м» или «кВт / м³» объединяют два разных
   измерения и требуют нескольких полей.

Операторы и допуски из матрицы **не менялись**: `delta`, `ge`, `tolerance_abs`, `tolerance_rel`
остались как были. Менялся только экстрактор — с каталожного скелета на рабочие якоря
с нормализацией `nfc / collapse_spaces / decimal_comma / strip_unit` и двойным чтением.

## Результат

| Решение | Правил |
|---|---|
| переведено в `executable` текстом | 6 |
| осознанно оставлено `extractor_missing` | 40 |
| **всего в выборке number** | **46** |

Покрытие на момент этого триажа: `executable` 38 → 44, `extractor_missing` 89 → 83.
AR-040 затем вышел из выборки (`extractor.type=geometry`).
SPZU-025 и SPZU-026 вышли (`extractor.type=contour_area`): один замкнутый прямоугольник,
площадь в м², несколько контуров не суммируются.
IOS2-071 вышел (`extractor.type=element_table`): марка строки и одно число,
разный набор марок не склеивается.
Живое покрытие 55 / 72.
Несколько пар штрихов не выбираются. Gate J не закрывается, 132/132 не заявляется.

У каждого правила четыре фикстуры: совпадение → `AUTO_NO_DIFFERENCE`, расхождение за
допуском → `CANDIDATE`, отсутствие обязательной стадии → `MISSING_EVIDENCE`, нечитаемое
значение → `LOW_QUALITY`. Автомат не ставит `CONFIRMED_VIOLATION`.

Отдельно закрыты типовые ловушки русских ТЭП: десятичная запятая («72,4» = «72.4») и
разделитель разрядов неразрывным пробелом («1 250 000» = «1250000»).

## Границы

- Шесть новых правил проверены на синтетических фикстурах, а не на контрольной выборке
  реальных комплектов: это заявка на исполнимость, а не измеренная точность.
- Для ZU-128 сторона РД часто лежит в подписи узла кровли. Если подписи нет, правило честно
  отдаёт `LOW_QUALITY`, а не подбирает ближайшее число.
- Для SM-132 допуск относительный (5 %): уточнение сметы в РД не должно шуметь,
  но и «пересчёт на 30 %» не должен молчать.
- Gate J остаётся открытым.
