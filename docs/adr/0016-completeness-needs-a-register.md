# ADR-0016: полнота комплекта считается по реестру

Статус: принят 26.09.2026.

## Контекст

Ответ организатора (сводная таблица, пункт 30): полнота — это сравнение
фактического manifest с ожидаемым составом объекта, стадии, раздела и
применимости параметров. Реестр приходит из карточки объекта или задаётся
инспектором. Пока реестра нет, комплект нельзя объявить полным:
`PARTIALLY_LOADED` или `CLARIFICATION_REQUIRED`.

Практика информационного менеджмента (ISO 19650): статус контейнера
сверяют с планом поставки информации, а не с тем, что в папке стадии
появился хотя бы один файл.

## Решение

1. `detect_scenario` возвращает `FULL` только при явном
   `expected_composition_declared=True` и трёх загруженных стадиях без
   `PARTIAL`.
2. Без этого флага три загруженные стадии дают `PARTIALLY_LOADED`.
   Живой процесс реестра не хранит, поэтому сам `FULL` не ставит.
3. Список отсутствующих элементов (тип, стадия, параметр, основание)
   не выдумывается: без реестра нечего перечислять.

## Последствия

Сценарии `PD_RD_ONLY`, `PD_ID_ONLY`, `RD_ID_ONLY` и `SINGLE_ONLY`
по-прежнему описывают, каких стадий нет. Это не заявление, что имеющиеся
файлы закрывают перечень документации.
