# ADR-0006. Сверяем документы, а не проект с нормой

**Статус:** принято 17.09.2026.

## Контекст

П. 1.2 ТЗ ставит задачу сравнить ПД, РД и ИД. П. 9.5 приводит таблицу, где
пример выглядит как сравнение с СНиП («2,4 против 2,5»). Если реализовать
второй смысл, ложные нарушения заполнят протокол: норма из ТЗ, действующая
норма и фактический проект разъедутся независимо от качества комплекта.

Нормативный реестр уже разделён на контракт организатора и overlay
(инвариант 6, `NORMATIVE_REGISTRY.md`). Не хватало явного запрета: автомат
не выносит «не соответствует СНиП».

## Решение

1. Компаратор сравнивает извлечённые значения **между стадиями** комплекта
   (ПД↔РД, при наличии — с ИД). Порог и единица — из строки матрицы, не из
   «знания модели о норме».
2. Overlay действующей нормы показывается инспектору как справка. Он не
   меняет `finding_status` и не переписывает `matrix_version`.
3. Нет стадии или файла → `MISSING_EVIDENCE` / `NOT_APPLICABLE`, не нарушение.
4. Документ есть, параметр не извлечён → `LOW_QUALITY` или `ABSTAIN`, не
   `NEGATIVE_VERIFIED` и не `CONFIRMED_VIOLATION`.

## Последствия

Тест «норма из таблицы 4» не является сценарием поставки. Free-search вне
132 строк (`FREE-HEATING-001`) остаётся вне матрицы, не 133-м правилом.
