# ADR-0008: object scope обязателен на HTTP-границе

Статус: принят.

## Контекст

Red Team RT-H обнаружил S0: API проверял роль, но не связывал субъект с
`object_id`. Зная `process_id` или `finding_id`, инспектор другого объекта мог
читать статус, протокол и аудит, подтвердить чужую находку, менять состояние
проверки и инициировать выгрузку. Изолированная функция
`check_object_access()` существовала, но HTTP-обработчики её не вызывали.

Это нарушает ТЗ §9.1 и stop-ship №1 из `docs/RED_TEAM.md`. Отдельные unit-тесты
чистой функции не доказывали защиту реальной точки входа.

## Решение

До подключения OIDC временный Bearer-контракт использует форму:

`Bearer <actor_id>@<object_id>/<ROLE>[,<ROLE>]`

Каждая операция над объектом выполняет две независимые проверки:

1. RBAC разрешает операцию роли;
2. непустой object scope токена точно совпадает с `ProcessRecord.object_id`.

Для новой загрузки scope также должен совпасть с `object_id` формы. При
дозагрузке сначала проверяется существующий процесс, затем выполняются чтение
файла, изменение состояния и запись. Проверка находки выполняется по объекту
процесса до вызова `review_finding`.

Отсутствующий scope закрывается по умолчанию. Токен без scope допустим только
для необъектных операций вроде `/system/capabilities`. Глобальный системный
доступ не кодируется как `None`: для него нужен отдельный доверенный путь.

## Доказательство

HTTP-регрессии проверяют 403 и отсутствие побочного эффекта для другого
объекта при:

- чтении status, protocol и audit;
- дозагрузке;
- review по известному `finding_id`;
- verify, complete, finalize и unfinalize;
- sync во внешнюю ИС.

Отдельно проверяются токены без scope и неоднозначные формы principal.

## Последствия и границы

- текущий формат — временная заглушка, не криптографическая аутентификация;
- перед production требуется OIDC/JWT validation: подпись, issuer, audience,
  expiration, revocation и доверенный claim object/tenant;
- ADMIN и SUPERVISOR не получают неявный cross-object доступ;
- отказ происходит до бизнес-мутации, а cross-object попытка не пишет review,
  не меняет состояние и не прикрепляет файл.
