# ADR-0013: новые источники утверждения ждут письменный ответ

Статус: принят.

## Контекст

Бриф недели 23.09 предлагает расширить `approval_status`: доверенные поля
индекса пакета, штамп «В производство работ» на РД и признак положительного
заключения экспертизы как доказательство, что ПД является эталоном. На
созвоне 16.09 заказчик отложил перечень полей индекса в письменный ответ.
Вопрос 21 в `docs/QUESTIONS_TO_ORGANIZER.md` этот перечень запрашивает и
имеет статус «Не отправлено».

ADR-0007 уже фиксирует, что эталоном становится только явная графа
«Утвердил» / «утв.» / «утверждён» / `approved` вместе с ФИО в той же строке
штампа, либо явный `SELECT_REVISION` инспектора. «Согласовано» и ГИП
недостаточны. Инвариант 5 не позволяет выбирать эталон при отсутствии
признака утверждения.

## Решение

До артефакта письменного ответа организатора по вопросу 21 действуют только
источники ADR-0007:

1. заполненная графа утверждения и ФИО в штампе, с координатами токенов;
2. явный выбор инспектора `POST .../revisions/{file_id}/select` с комментарием.

Не становятся `APPROVED`:

- поля индексных файлов и манифеста пакета;
- штамп «В производство работ» на РД, даже если рядом есть фрагмент;
- упоминание заключения экспертизы без отдельного письменного разрешения
  и без фрагмента, который ADR-0007 уже считает утверждением;
- «Согласовано», ГИП, подпись без графы «Утвердил», дата без ФИО.

Иначе статус остаётся `UNKNOWN`, resolver возвращает `CLARIFICATION_REQUIRED`,
компаратор не запускается. Gold TRAIN_PUBLIC для ПД F0171 остаётся без
попадания, пока в самом штампе нет графы «Утвердил» и ФИО.

Поле `approval_basis` не добавлять, пока не появился новый разрешённый
источник: сейчас оно только продублировало бы ADR-0007.

## Последствия

- бриф Д0 не разблокирует 0/6 заменой политики эталона;
- следующий агент не трактует «В производство работ» как approval;
- после письменного ответа политика меняется отдельным ADR и тестом, не
  правкой этого текста задним числом.
