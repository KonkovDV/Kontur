# ADR-0003. Редакция определяется до сравнения

**Статус:** принято 15.09.2026.

## Контекст

ТЗ п. 9.1: устаревшая редакция не может быть эталоном; при конфликте редакций
или отсутствии признака утверждения система обязана вернуть
`CLARIFICATION_REQUIRED`. Сравнение по устаревшему листу даёт ложные нарушения
по всему объекту — самый дорогой класс ошибки в задаче.

## Решение

Порядок разрешения эталона, детерминированный и тестируемый:

1. точный `object_id`;
2. `doc_stage` + `discipline` + `document_code` + лист;
3. явная связь `predecessor`/`successor`;
4. `approval_status`;
5. `approval_date`;
6. доменный парсер порядка редакций;
7. согласованное изменение или замена листа;
8. конфликт → `CLARIFICATION_REQUIRED`, кандидаты не формируются.

Обязательный adversarial-набор: одинаковые имена с разными хешами; новая
неутверждённая редакция; старая утверждённая; пропущенный predecessor; две
утверждённые редакции одной датой; частичная замена листа; редакция в штампе
расходится с именем файла.

## Последствия

Resolver — отдельный модуль с собственной метрикой (связка ≥0,95 по ТЗ,
внутренняя цель ≥0,99) и отдельно измеряемым stale-revision FPR.
