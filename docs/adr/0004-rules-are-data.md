# ADR-0004. 132 параметра — данные, а не код

**Статус:** принято 15.09.2026.

## Контекст

ТЗ п. 8 задаёт таблицу `Params` с текстовым `trigger_logic` (например, «< 0.9 м»).
Текстовый триггер нельзя исполнять напрямую: он неоднозначен и не тестируем.
Модуль 8 ТЗ требует менять пороги без перекодирования системы.

## Решение

1. `trigger_logic` компилируется в типизированное правило Rule DSL
   (`contracts/schemas/rule.schema.json`), проходит валидацию схемы и unit-тесты.
2. Правило содержит: `code`, `section`, `matrix_version`, `applicability`,
   селекторы источников ПД/РД/ИД, тип экстрактора, единицу и нормализацию,
   оператор, допуск и правило округления, требуемые роли доказательств,
   нормативные ссылки с периодом действия, отображение отказов и
   `review_priority` (очередь проверки, не юридическая тяжесть).
3. Реестр публикует честное покрытие по каждому параметру:
   `executable` / `extractor_missing` / `source_missing` / `advisory` /
   `not_applicable`. «Поддерживаем 132 параметра» без этой разбивки не заявляется.
4. LLM может предложить черновик правила; в production попадает только
   подписанный пакет правил с тестами и результатом юридической проверки.

## Последствия

Смена редакции норматива или порога — это релиз пакета правил с diff и
возможностью отката, а не правка кода.
