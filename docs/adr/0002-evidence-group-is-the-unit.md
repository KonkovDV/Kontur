# ADR-0002. Единица результата — evidence_group

**Статус:** принято 15.09.2026, уточнено 16.09.2026.

## Контекст

ТЗ п. 9.2 и 14.1: единица разметки и оценки —
`объект + параметр/атомарное правило + применимые утверждённые редакции +
доказательные фрагменты с координатами`.

Статусы качества данных (`MISSING_EVIDENCE`, `NOT_APPLICABLE`) описывают
отсутствие источника. Требовать у них тот же набор фрагментов, что у
кандидата, либо запрещает честный отказ, либо провоцирует фиктивные
доказательства.

## Решение

1. Метрики считаются по `evidence_group`, никогда по страницам, файлам или строкам.
2. Предметная находка (`CANDIDATE`, `CONFIRMED_VIOLATION`, `NEGATIVE_VERIFIED`,
   внутренний `AUTO_NO_DIFFERENCE`) не персистится без: `evidence_group_id`,
   `rule_code`, ролей `expected`/`actual`, `file_id` + SHA-256 каждого
   источника, стадии, шифра, редакции, `approval_status`, листа/страницы,
   polygon в координатах источника и нормализованного polygon [0;1].
3. `MISSING_EVIDENCE` и `NOT_APPLICABLE` могут иметь пустой массив
   `fragments` и пустой `evidence_group_id`. Это сериализуемое отсутствие,
   а не дыра в схеме.
4. Составной кандидат дробится на атомарные находки; каждая получает своё
   решение и свои доказательства. Статуса `PARTIALLY_CONFIRMED` не существует.
5. Верный тип расхождения без верного доказательства не является true positive.

## Последствия

Хранилище доказательств неизменяемо: улучшение OCR порождает новую производную
версию извлечения, а не правку существующей записи.
