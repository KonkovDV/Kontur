# Политика данных и карантина

## Каталоги (все вне git)

| Каталог | Назначение | Доступ |
|---|---|---|
| `files/` | локальная копия поставки (gitignored) | открытые единицы — чтение; `РАЗМЕЧЕННЫЙ_TEST__213` — **карантин**, даже если лежит рядом с train |
| `data/incoming/` | исходные архивы как получены | только чтение после хеширования |
| `data/quarantine/` | `РАЗМЕЧЕННЫЙ_TEST__213.zip`, каталог `РАЗМЕЧЕННЫЙ_TEST_HIDDEN_ОРГАНИЗАТОР_213` и `annotated_documents` **скрытого теста** | **не открывать** |
| `data/work/` | распаковка train/validation | чтение и запись |
| `data/cache/` | рендер страниц по ключу `file_hash + page + dpi + preprocessing_version` | перестраиваемый |

Бюджет диска: не менее 300 ГБ NVMe. Поставка 15.09.2026 — ≈78 ГиБ только в
архивах, до распаковки. Страницы не рендерятся заранее пакетом — только по
требованию с кешированием.

## Реестр поставки

Состав архива описан в [`data/dataset/package_manifest.json`](../data/dataset/package_manifest.json),
объекты и разбиение — в [`data/dataset/objects.json`](../data/dataset/objects.json),
открытый gold — в [`data/dataset/gold_inventory.json`](../data/dataset/gold_inventory.json),
разбор и барьер доступа — в `backend/src/kontur/evaluation/dataset_package.py`.
Подробности: [`DATASET_PACKAGE.md`](DATASET_PACKAGE.md),
[`ORGANIZER_GOLD.md`](ORGANIZER_GOLD.md).

Карантин определяется двумя независимыми источниками: полем `access` в манифесте
и нормализованным именем пути (`evaluation/inventory.normalize` — схлопывает
повторяющиеся `_` и снимает регистр, включая кириллицу). Нормализация нужна не
для красоты: организатор прислал архив как `РАЗМЕЧЕННЫЙ_TEST__213.zip` с двумя
подчёркиваниями, и точное сравнение имён его пропускало. Расхождение двух
источников — падение теста `test_dataset_package.py`.

Имя каталога `annotated_documents` само по себе **не** карантин: тот же каталог
есть в открытом `РАЗМЕЧЕННЫЙ_TRAIN_PUBLIC_203.zip`. Карантин — маркеры скрытого
теста (`test_213`, `test_hidden`, `hidden_организатор`) и дерево
`data/quarantine/`.

## Неприкосновенные правила

1. До распаковки сохранить SHA-256 каждого архива; после — сверить `SHA256SUMS.jsonl`.
2. Скрытый тест не используется для выбора модели, prompt, regex, порога,
   препроцессинга OCR и ручных исправлений. То же относится к объекту
   `OBJ-RECHNIKOV-7-7`: его PDF могут лежать в открытом пакете, но
   `require_labeled_train_object` пускает только
   `OBJ-NOVOSLOBODSKAYA` и `OBJ-TYUMENSKAYA-5-GOLD-SEED`.
3. Разбиение train/validation — строго по `object_id`: все страницы, документы
   и редакции одного объекта лежат в одном наборе. Пересечение должно быть 0.
4. Мутации одного оригинала не расходятся между наборами.
5. Каждый эксперимент пишет `dataset_version`, `matrix_version`, `model_version`,
   git SHA и `input_manifest_hash`.
6. Файлы с одинаковым content hash — один источник, независимо от имени и пути.
7. Имя файла не является доказательством: перед чтением артефакт проходит через
   `dataset_package.require_open` (манифест **или** детектор имён — отказ) либо
   через `inventory.require_path_open`. Новые варианты имён карантина добавляются
   в `QUARANTINE_MARKERS` вместе с тестом.
8. Пока SHA-256 не внесены, переименование скрытого теста в имя без маркеров
   **вне** `data/quarantine/` детектор не поймает. Это остаточный S0 до закрытия
   пункта хешей в чек-листе Gate A. `hash_archives` пропускает карантинные
   имена и хеширует остальные: наличие `РАЗМЕЧЕННЫЙ_TEST__213.zip` в
   `data/incoming/` не валит партию. Карантинный архив этим контуром не
   читается и не хешируется.

## Что обязан вывести инвентаризатор

Архив → объект → стадия → дисциплина → `document_code` → редакция → утверждение;
число файлов, страниц, MIME, объём; vector-only / raster-only / hybrid;
DPI, Rotate, MediaBox, CropBox, шрифты, embedded text, OCR-слой; доля
повреждённых, зашифрованных и пустых страниц; дубликаты по SHA-256 и
near-duplicates по perceptual hash; наличие подписей, печатей, штампов,
рукописных зон; распределение bbox и классов доказательств; пересечение
train/validation/test по объектам; баланс классов по разделу, коду параметра,
статусу и `reason_code`; аудит утечки по именам, шаблонам, водяным знакам и
дубликатам.

Реализация: `backend/src/kontur/evaluation/inventory.py` (скелет; SHA-256 ещё
не считаются — `pending_hashes` не пуст).
