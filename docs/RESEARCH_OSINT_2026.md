## К какому состоянию относится записка

На `main` 28.09 конкурсный вертикальный срез уже есть: голова редакции по
шифру, единственная голова ПД без штампа сравнивается с
`approval_basis=SOLE_HEAD` ([ADR-0017](adr/0017-sole-head-without-stamp.md)),
сравнение помещений перебирает все пары листов, ключ `location` комнаты —
номер как в разметке (`140`), DOCX читается абзацами и таблицами, протокол
материализуется атомарно, пакет формы лежит в [`submission/`](../submission/README.md).
Код передаётся заказчику без открытой лицензии; лицензии зависимостей —
[`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md).

Публичный gold после этого среза (Тюменская, режим `location`): матрица
0 из 6, свободный поиск 0 из 4, `unlabeled_positive` 0, остановка «якорь или
число не найдены». Пороги комнат по этим строкам не подбирались. Это не порог
ТЗ и не закрытие гейта J. Wilson на 6 из 6 всё равно ниже порога recall:
для нижней границы нужно n≥16.

OCR на `main`: сначала вектор pdfium, пустой слой — локальный eslav PP-OCRv5,
затем Tesseract. SILVER 26.09, корпус `PDF_TEXT_LAYER`, n=5935, coverage=1:
eslav PP-OCRv5, нижняя граница Wilson доли строк с CA не ниже 0,95 — около
0,663 (`gate_i_low` около 0,632). Пороги 0,95 и 0,97 не взяты. `ocr_text`
остаётся `MEASURED`. Это не GOLD. Гейт I открыт.

## Что из записки 21.09 больше не является живым фактом

1. Покрытие 44 executable / 83 extractor_missing устарело. Живая разбивка —
   55 / 72 / 1 / 4.
2. Многомодельный bake-off на frozen GOLD (PaddleOCR-VL, MinerU2.5, Docling,
   Qwen) не запускался и в зачётный офлайн-прогон не переносился. Измеренный
   путь — pdfium и локальный OCR, см. выше.
3. Каталог adversarial-фикстур есть: `backend/tests/adversarial/`, по одному
   примеру в наборах RT-A…RT-I ([`RED_TEAM.md`](RED_TEAM.md)). Изоляция VLM
   от текста страницы в system prompt остаётся открытым
   [#84](https://github.com/KonkovDV/Kontur/issues/84).
4. Очередь PR как отдельный документ снята. Следствие литературы — раздел
   ниже, а не список незакрытых pull request.

Инварианты протокола, которые записка держала и которые остаются:

- `assemble_protocol()` намеренно без `kind` / `assembled`: схема ТЗ
  `additionalProperties: false`. Predicate
  `kind IS DISTINCT FROM 'materialized'` запрещён.
- Fail-closed sync: `PROTOCOL_FINALIZED` и hex `payload_sha256`.
- Publisher confirm брокера — не `SYNCED` ([ADR-0011](adr/0011-sync-lifecycle-and-manual-retry.md)).
  Inbox ACK — локальное получение, не бизнес-ACK РиН
  ([ADR-0012](adr/0012-transactional-inbox.md)).
- Три контура готовности ведутся чеклистом. Процента «готовности по ТЗ» нет.
- PDF — недоверенный ввод. Модель пишет кандидата и черновик объяснения.
  `finding_status` пишет детерминированный компаратор, `CONFIRMED_VIOLATION` —
  только инспектор ([ADR-0001](adr/0001-llm-never-sets-verdict.md)).

## Глубокий срез SOTA (arXiv, поиск 21.09.2026)

Проверяли один вопрос: где в 2026 году проходит граница между «читается
автоматически» и «нужен человек», чтобы не заявлять исполнимость там, где её нет.

### 1. Разбор печатных документов вышел на плато

Парсинг печатной страницы перестал быть узким местом. WildHandBench
(arXiv:2608.17012, 24.08.2026) фиксирует у лучшей модели 96.34 на печатном
срезе OmniDocBench; GLM-OCR (arXiv:2605.14930, 21.05.2026) даёт композит 94.62.
FinixDoc (arXiv:2608.16884, 24.08.2026) прямо называет эти бенчмарки насыщенными
и предлагает мерить сложные финансовые документы.

**Вывод для Контура.** Смена движка ради «более новой OCR» на срезе 28.09 не
делалась. Второе чтение уже есть: вектор pdfium и независимый кроп локальным
OCR. Расхождение источников даёт отказ, а не уверенный вердикт.

### 2. Тонкое восприятие и трассируемость доказательства — слабое место

«State-Conditioned Visual Evidence Retrieval» (arXiv:2608.19233, 27.08.2026)
показывает, что модели уверенно отвечают, но плохо указывают на
фрагмент-основание. DocTrace (arXiv:2608.02149, 04.08.2026) вводит графы
трассируемых доказательств именно потому, что ответ без указания места в
документе непригоден для аудита.

**Вывод для Контура.** `evidence_group` с SHA-256, страницей и polygon —
основной продукт ([ADR-0002](adr/0002-evidence-group-is-the-unit.md)).
Инспектор проверяет доказательство. Предметная находка без фрагмента не
сохраняется.

### 3. Подсчёт объектов — самая слабая способность VLM

«The Count Is There, but Misaligned» (arXiv:2607.07615, 10.07.2026), ABACUS
(arXiv:2606.18210, 22.06.2026), RT-Counter / TOOC (arXiv:2606.13446, 16.06.2026)
сходятся: счёт однотипных объектов проваливается даже у моделей, хорошо
читающих текст. Тот же вывод даёт AECV-Bench на дверях и окнах.

**Вывод для Контура.** Правила с подсчётом объектов на плане остаются
`extractor_missing`. Обещать их через VLM в этом контуре нельзя. Триаж:
[`NUMBER_FAMILY_TRIAGE.md`](NUMBER_FAMILY_TRIAGE.md),
[`EXTRACTOR_FAMILY_TRIAGE.md`](EXTRACTOR_FAMILY_TRIAGE.md).

### 4. Чертежи требуют вектора, а не растра

PolarSym (arXiv:2608.06244, 12.08.2026), «Text-Aided Multi-Modal Panoptic
Symbol Spotting for CAD Floor Plan Drawings» (arXiv:2607.10286, 14.07.2026),
ArchCAD-400K, RealCADBench (arXiv:2609.02871, 03.09.2026), MechReason
(arXiv:2608.15101, 21.08.2026), Enginuity (arXiv:2606.03410, 02.06.2026) и
«When Should a Network Emit Geometry» (arXiv:2608.18704, 26.08.2026) показывают
одно и то же: результат на чертежах лучше, когда на входе векторные примитивы,
а не картинка страницы.

**Вывод для Контура.** Графический контур опирается на векторный слой PDF.
Правила `geometry` остаются `extractor_missing`. DWG в зачётном контуре не
читается (`GAP-DWG`).

### 5. Таблицы: направление, прямо релевантное AR-050

Doc2DB-Bench (arXiv:2608.08459, 09.08.2026) ставит задачу «документ →
реляционно верная база»: важна не распознанная сетка, а корректные связи между
сущностями. POTATR (arXiv:2606.09788, 08.06.2026) делает разбор страницы-таблицы
через image-to-graph, TEAR (arXiv:2609.15205, 14.09.2026) добавляет к извлечению
рекомендацию атрибутов.

**Вывод для Контура.** AR-050 «ведомость отделки по помещениям» остаётся
`extractor_missing` с причиной `table_composite`: нужна таблица
«помещение → материал», а не одиночное значение по якорю. DOCX-таблицы
читаются как текст; это не табличный экстрактор правила.

### 6. Проверка соответствия: правила как данные

ARCHER «Agentic Rule and Compliance Harness for Executable Regulations»
(arXiv:2607.21883, 28.07.2026) и «Automating Geometry-Intensive Compliance
Checking in BIM» (arXiv:2606.08715, 10.06.2026) приходят к одной архитектуре:
норма компилируется в исполняемое правило, а LLM используется для сопоставления
и объяснения, но не для интерпретации текста нормы на лету. «From Naive RAG to
Deep Agentic Retrieval» (arXiv:2607.24791, 28.06.2026) добавляет агентный поиск
по регуляторике. «Trustworthy Agentic AI» (arXiv:2609.22712, 19.09.2026)
описывает режимы отказа агентных систем и требует границ полномочий.

**Вывод для Контура.** Матрица лежит данными (`data/matrix/rules/*.json`),
экстракторы и компараторы детерминированы, роль модели — кандидат и черновик
объяснения. Запрет автомату ставить `CONFIRMED_VIOLATION` совпадает с
требованием ограничения полномочий. Сверка идёт ПД↔РД↔ИД. Overlay нормы вердикт
матрицы не меняет ([ADR-0006](adr/0006-compare-documents-not-norms.md)).

## Bake-off, который не является зачётом

Кандидаты, которые записка 21.09 оставляла на один будущий frozen GOLD:
pdfium (канон вектора), Tesseract (независимый crop), PaddleOCR-VL,
MinerU2.5, Docling как adapter, Qwen только advisory. Главная метрика такого
прогона — silent numeric error, n=50–100 разрешённых страниц, корпус без
TEST_HIDDEN.

Из этого списка на `main` работают pdfium и локальный OCR (eslav PP-OCRv5,
Tesseract). PaddleOCR-VL, MinerU, Docling и Qwen на GOLD Контура не
запускались. Повторять прогон ради рейтинга до дедлайна 29.09 не нужно:
стек заморожен, гейт I по SILVER не закрывается.
