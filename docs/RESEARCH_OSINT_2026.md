## Поправки к внешним memo

1. SHA `695d9c7` / «PR #64 открыт» — устарели. `main` на атомарном протоколе,
   outbox/inbox, JWT boundaries (PR #64–#73).
2. `assemble_protocol()` **намеренно** без `kind`/`assembled`: схема ТЗ
   `additionalProperties: false`. Predicate
   `kind IS DISTINCT FROM 'materialized'` **запрещён**.
3. Fail-closed sync: `PROTOCOL_FINALIZED` + hex `payload_sha256`. Missing
   `assembled` — штатный JSON.
4. Publisher confirm брокера **не** `SYNCED` (ADR-0011). Inbox ACK — локальное
   получение, не бизнес-ACK РиН (ADR-0012).
5. Три контура готовности ведутся JSON-чеклистом, без процента «по ТЗ».
6. **PaddleOCR-VL:** в первичных карточках уверенно подтверждена линейка
   **1.5** (0.9B, OmniDocBench v1.5 self-reported). Упоминание 1.6 требует
   повторной проверки model card, лицензии и доступности весов.
7. OmniDocBench / ParseBench не репрезентируют российские ПД/РД/ИД и не
   заменяют object-level GOLD. Оценка — символы, поля, таблицы, reading
   order, bbox, semantic mapping, правило; не «качество Markdown».
8. MinerU2.5 (coarse layout + native crop) логичен для A0/A1, но только с
   фиксацией digest кода/весов, лицензии, VRAM и русского AEC GOLD.
9. Docling — MIT baseline/adapter с bbox, не доменная модель Kontur.
10. Prompt injection в PDF (OWASP indirect/multimodal): содержимое документа
    — недоверенные данные; VLM без tool/write; текст не в system prompt;
    schema-constrained candidate + deterministic validation.

## Глубокий срез SOTA (arXiv, поиск 21.09.2026)

Проверяли один вопрос: где в 2026 году реально стоит граница между «читается автоматически»
и «нужен человек», чтобы не заявлять исполнимость там, где её нет.

### 1. Разбор печатных документов вышел на плато

Парсинг печатной страницы перестал быть узким местом. WildHandBench (arXiv:2608.17012,
24.08.2026) фиксирует у лучшей модели 96.34 на печатном срезе OmniDocBench; GLM-OCR
(arXiv:2605.14930, 21.05.2026) даёт композит 94.62. FinixDoc (arXiv:2608.16884, 24.08.2026)
прямо называет эти бенчмарки насыщенными и предлагает мерить сложные финансовые документы.

**Вывод для нас:** дальнейшая борьба за OCR печатного текста даёт мало. Bake-off нужен не ради
рейтинга, а ради второго чтения и расхождений между движками.

### 2. Тонкое восприятие и трассируемость доказательства — слабое место

«State-Conditioned Visual Evidence Retrieval» (arXiv:2608.19233, 27.08.2026) показывает, что
модели уверенно отвечают, но плохо указывают на фрагмент-основание. DocTrace (arXiv:2608.02149,
04.08.2026) вводит графы трассируемых доказательств именно потому, что ответ без указания места
в документе непригоден для аудита.

**Вывод для нас:** `evidence_group` с координатами фрагмента — не украшение, а основной продукт.
Инспектор проверяет доказательство, а не текст вывода.

### 3. Подсчёт объектов — самая слабая способность VLM

«The Count Is There, but Misaligned» (arXiv:2607.07615, 10.07.2026), ABACUS
(arXiv:2606.18210, 22.06.2026), RT-Counter / TOOC (arXiv:2606.13446, 16.06.2026) сходятся:
счёт однотипных объектов проваливается даже у моделей, хорошо читающих текст.

**Вывод для нас:** 14 правил, требующих подсчёта и пересечения зон, остаются
`extractor_missing`. Обещать их через VLM в этом контуре нельзя.

### 4. Чертежи требуют вектора, а не растра

PolarSym (arXiv:2608.06244, 12.08.2026), «Text-Aided Multi-Modal Panoptic Symbol Spotting for CAD
Floor Plan Drawings» (arXiv:2607.10286, 14.07.2026), ArchCAD-400K, RealCADBench
(arXiv:2609.02871, 03.09.2026), MechReason (arXiv:2608.15101, 21.08.2026), Enginuity
(arXiv:2606.03410, 02.06.2026) и «When Should a Network Emit Geometry» (arXiv:2608.18704,
26.08.2026) показывают одно и то же: результат на чертежах резко лучше, когда на входе векторные
примитивы, а не картинка страницы.

**Вывод для нас:** графический контур строим на векторе PDF/DWG-экспорта. До этого — `geometry`
без заявления исполнимости.

### 5. Таблицы: новое направление, прямо релевантное AR-050

Doc2DB-Bench (arXiv:2608.08459, 09.08.2026) ставит задачу «документ → реляционно верная база»:
важна не распознанная сетка, а корректные связи между сущностями. POTATR (arXiv:2606.09788,
08.06.2026) делает разбор страницы-таблицы через image-to-graph, TEAR (arXiv:2609.15205,
14.09.2026) добавляет к извлечению рекомендацию атрибутов.

**Вывод для нас:** правила вида «ведомость отделки по помещениям» (AR-050) относятся к этому
классу задач, а не к поиску одиночного значения по якорю. Это подтверждает решение оставить
их `extractor_missing` с причиной `table_composite`.

### 6. Автоматизированная проверка соответствия: правила как данные

ARCHER «Agentic Rule and Compliance Harness for Executable Regulations» (arXiv:2607.21883,
28.07.2026) и «Automating Geometry-Intensive Compliance Checking in BIM» (arXiv:2606.08715,
10.06.2026) приходят к одной архитектуре: норма компилируется в исполняемое правило, а LLM
используется для сопоставления и объяснения, но не для интерпретации текста нормы на лету.
«From Naive RAG to Deep Agentic Retrieval» (arXiv:2607.24791, 28.06.2026) добавляет к этому
агентный поиск по регуляторике. «Trustworthy Agentic AI» (arXiv:2609.22712, 19.09.2026)
описывает режимы отказа агентных систем и требует границ полномочий.

**Вывод для нас:** выбранная архитектура — матрица как данные (`data/matrix/rules/*.json`),
детерминированные экстракторы и компараторы, LLM только как `semantic_candidate` — совпадает
с независимо полученным выводом двух групп. Запрет автомату ставить `CONFIRMED_VIOLATION`
согласуется с требованием ограничения полномочий.

### Что из этого следует для очереди PR

| Направление | Что делаем | Что не обещаем |
|---|---|---|
| Печатный текст | второе чтение и сверка движков | прирост от «более новой OCR» |
| Трассируемость | координаты фрагмента в `evidence_group` | ответ без указания места |
| Подсчёт | оставляем `extractor_missing` | подсчёт через VLM |
| Чертежи | вектор как вход, `geometry` | распознавание растровой страницы чертежа |
| Таблицы | отдельный табличный контур после подачи | AR-050 как текстовое правило |
| Норма | правило как данные + проверяемый `normative_refs` | интерпретация текста нормы LLM |
