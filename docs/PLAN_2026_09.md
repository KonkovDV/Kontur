## Расхождения контрактов (адаптер, домен не трогаем)

Внешний контракт соревнования (`contracts/schemas/submission.schema.json`)
систематически отличается от внутренних схем — маппинг в
`kontur.evaluation.submission`:

1. **Статусы**: внешние `VIOLATION_PRESENT / NO_VIOLATION /
   MISSING_DOCUMENT / COMPARISON_IMPOSSIBLE` и `protocol_status: OK /
   WARNING / CRITICAL / ID_MISSING / RD_MISSING / PD_MISSING /
   COMPARISON_IMPOSSIBLE` ↔ внутренние `FindingStatus` (11 значений) и
   `review_priority` (HIGH/MEDIUM/LOW). Маппинг — отдельный адаптер;
   домен не правится под внешний enum.
2. **Коды**: внешний канон `PZ-001`/`IOS4-079`; короткие формы (`PZ-01`,
   `AR-14`) нормализуются `canonicalize_rule_code`. `FREE-HEATING-001` —
   `data/matrix/free_search.json`, не 133-я строка матрицы.
3. **Evidence**: внешний минимум — `(stage, file_id, pdf_page_number)`;
   внутренний инвариант строже (SHA-256, polygon source+norm). Внешняя
   схема — подмножество, экспорт тривиален; импорт внешних меток во
   внутренний формат требует догрузки хешей и геометрии.
4. **Критичность**: gold `criticality` (Критическое/Существенное) ≠
   `review_priority`. Это разные оси: юридическая тяжесть и очередь
   проверки; хранить обе, не смешивать.
5. **ИД-тройственность**: `stage: PD/RD/ID` совпадает, но `document_status:
   PD_RD_AVAILABLE_ID_NOT_REQUIRED_FOR_PAIRWISE_CHECK` подтверждает:
   попарная проверка ПД↔РД валидна без ИД — отсутствие стадии не нарушение
   (инвариант 4 соблюдается и в данных организатора).

## Порядок сборки вертикальных слайсов

Каждое правило проходит полный путь `source → extraction → compare → evidence →
review → protocol`, прежде чем берётся следующее. Горизонтальная разработка
«сначала все экстракторы» запрещена: она не даёт демонстрируемого результата.

Первые правила — по кодам каталога, с учётом золотых нарушений и типов
компараторов:

1. `PZ-001` (площадь застройки, м²) — число с допуском; триггер «расхождение
   контуров > 0». Источники: ПЗУ ТЭП ↔ ПП «Общие данные» ↔ техплан БТИ.
2. `KR-055` (класс бетона, Марка B) — enum-компаратор с направлением
   (понижение = нарушение, повышение — нет); есть 3 NO_VIOLATION-примера в gold.
3. `IOS4-079` (конфигурация вентустановок) — композиционное сравнение, покрыто
   золотым VIO-0001; это единственное правило с готовой положительной парой.
4. `AR-041` (ширина эвакуационных дверей, м) — число с нижней границей 0,9 м.
5. `IOS4-078` (сечения воздуховодов) — второй золотой кластер (VIO-0003).

Покрытие всех 132 строк сейчас `extractor_missing`, кроме `PZ-001`
(`coverage: executable`: якорь + число + delta на токенах страницы).
Канонические коды — трёхзначные (`PZ-001`);
короткие формы из текстов (`PZ-01`, `KR-55`) — display-алиасы.
