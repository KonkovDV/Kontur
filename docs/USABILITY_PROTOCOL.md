# Протокол юзабилити (ТЗ п. 9.3)

Форма замера для RT-2609-21. Находка закрывается только после сессии с 5
инспекторами, не по факту появления этого файла или UI-рекордера. Проводится
до гейта K (26.09.2026).

## Целевые метрики

| Показатель | Порог ТЗ | Как фиксируется |
|---|---|---|
| Время на протокол (один объект) | ≤ 30 мин | `session_started_at` / `session_finished_at` в JSON и секундомер наблюдателя |
| Кликов до решения по одной находке | ≤ 3 | `clicks_to_decision` в JSON-рекордере |
| Ошибок навигации | — | устная ремарка / экранная запись |

## Состав участников

5 инспекторов с разным опытом работы с ПД/РД/ИД.  
Задача: обработать одинаковый **учебный** комплект (не TRAIN_PUBLIC и не
скрытый тест). Рекордер не загружает PDF и не собирает протокол Приложения 2.

## Сценарий сессии

1. **Инструктаж ≤ 5 мин** — интерфейс, цель, что считается «решением».
   Инструктаж **не** входит в 30 минут.
2. Ввести обезличенный код участника; не вводить ФИО и контакты.
3. Нажать **«Начать учебную сессию»** — с этого момента идёт таймер.
4. **Пять учебных карточек**: минимум 1 числовая, 1 текстовая, 1 со статусом
   `MISSING_EVIDENCE`.
5. Для `MISSING_EVIDENCE` единственное действие — «Принять: нет документа».
   «Подтвердить» и «Отклонить» на этой карточке недоступны: отсутствие
   документа не нарушение.
6. Скачать JSON `kontur-usability-v1` и передать наблюдателю.
7. Сверка с Приложением 2 — отдельный шаг рабочего протокола, не этот
   рекордер. В JSON поле `closes_gate_k` всегда `false`.

Это инженерный инструмент замера кликов, а не результат Gate K и не замена
наблюдателю.

Заполняется наблюдателем по JSON и экранной записи. Сводка — в
`docs/USABILITY_RESULTS.md`; сырые JSON не коммитятся, если в них появились
персональные или служебные данные.

## Критерий успеха

Все 5 инспекторов: время ≤ 30 мин **и** максимум кликов до решения каждой
находки ≤ 3. Среднее приводится как дополнительная метрика, но не скрывает
единичный провал.  
Хотя бы один провал → задача в backlog до гейта M (28.09).
