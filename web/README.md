# Рабочее место инспектора

PDF-first, не просмотрщик моделей. Экран верификации — единственное место, где
появляется `CONFIRMED_VIOLATION`, поэтому его требования жёстче остальных.

## Обязательная компоновка

Цель — три синхронизированные панели ПД / РД / ИД (файл, шифр, редакция,
утверждение, страница с полигоном). Сейчас две панели `expected` / `actual`
с `polygon_norm` (bbox производный), raw/normalized, SHA-256 и карточкой
правила. Живой PDF через `pdfjs-dist` ещё не подключён: учебный срез рисует
контур на нормализованной странице. Третья панель ИД — долг, не готовность.

Между панелями — карточка правила: код, допуск компаратора, extracted values,
delta, disagreement, решение инспектора, audit. Нормативная ссылка overlay
не меняет вердикт матрицы. «≤3 клика» — не более трёх сознательных действий
инспектора на находку (открыть → подтвердить или отклонить с причиной).

## Требования, проверяемые на юзабилити-тесте (ТЗ п. 9.3)

- полный цикл протокола (132 параметра, 14 нарушений) — до 30 минут;
- не более 3 кликов на одну находку;
- тестирование на 5 инспекторах с доработкой до достижения метрик.

## Инварианты интерфейса

1. «Подтвердить» не является предвыбранным или сфокусированным по умолчанию
   действием: automation bias измеряется и не поощряется.
2. Отклонение без `reason_code` невозможно отправить.
3. Комплектность и статусы качества данных показываются отдельным списком,
   визуально не смешиваясь с кандидатами.
4. Составной кандидат нельзя подтвердить целиком — только после разделения
   на атомарные находки.
5. `SUSPICION` помечается как гипотеза вне матрицы и не попадает в счётчик
   нарушений.
6. Отсутствие доказательства показывается как отсутствие, а не как зелёный
   результат.

Сейчас в `src/` — учебный рекордер пяти evidence-карточек
(`kontur.evidence_card.v1` + `kontur-usability-v1`). `pdfjs-dist` в
зависимостях, кропы страницы из байт PDF ещё не грузятся. Рекордер не
закрывает Gate K: нужны пять очных сессий в `docs/USABILITY_RESULTS.md`.
